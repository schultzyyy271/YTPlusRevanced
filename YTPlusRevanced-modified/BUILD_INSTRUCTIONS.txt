WHY THE PREVIOUS CRASH HAPPENED:
The previous Claude session tried to fix the LC_LOAD_UPWARD_DYLIB issue by binary-patching 
the compiled dylibs (changing load command bytes directly). This corrupted iSponsorBlock.dylib's
load command string offset, causing dyld to reject it on launch with:
  "load command #12 string offset (16384) outside its size (24)"

The fix is simply to rebuild from source - the Makefiles already have the correct LDFLAGS
that prevent the bad load command from being generated in the first place.
